# can-server — Садко на шине

Тестовый стенд для `message-gateway`: изображает стороннее устройство, которое
раздаёт по шине время и координаты, и принимает от технического зрения кадр
обнаружений. Роль зеркальная по отношению к `testing/ws-server`, только шина
вместо WebSocket.

## Запуск

```
pip install -r requirements.txt

python server.py --mode slcan --device COM3          # USB-адаптер, Windows
python server.py --mode slcan --device /dev/ttyUSB0  # он же в Linux
python server.py --mode socketcan --iface can0       # штатный CAN ядра Linux
```

Страница: http://localhost:8766

`socketcan` есть только в Linux. На Windows работает режим `slcan` — сервер сам
открывает порт, выставляет скорость шины командой адаптера и говорит с ним
ASCII-протоколом Lawicel; внешний `slcand` не нужен.

Полезные флаги: `--bitrate` (250000), `--period` (500 мс), `--lat`/`--lon`
(базовая точка заглушки), `--port` (8766).

## Что уходит на шину

Раз в 500 мс, с адреса `0x61`, приоритет 6:

| ID | PGN | Сообщение | Раскладка |
|----|-----|-----------|-----------|
| `0x18FF0161` | FF01 | Дата, время, скорость | год, месяц, день, час, минута, секунда, скорость (2 байта LE, 0.01 м/с на бит) |
| `0x18FF0061` | FF00 | Координаты | широта: градусы, минуты+знак, секунды (2 байта LE, тысячные); долгота так же |

Время выдаётся в UTC. Знак полушария — не отдельный байт, а биты внутри байта
минут: бит 7 — N (E), бит 8 — S (W); ровно один из них обязан стоять.

Координаты выдуманные. Точка гуляет случайным блужданием вокруг базовой и не
уходит дальше пары километров: неподвижная заглушка не отличалась бы на странице
от залипшей выдачи, а случайная точка на всём шаре — от мусора на шине.

## Что принимается

| ID | PGN | Сообщение | Раскладка |
|----|-----|-----------|-----------|
| `0x00EF0071` | EF00 | Обнаружения | количество, тип, класс опасности, маска камер |

Байт камер — маска, а не номер: бит на камеру, поэтому в одном кадре видно сразу
несколько камер, поймавших обнаружение. На странице он показан побитово.

Чужой трафик шины в ленту не пишется, только считается: иначе он утопил бы в себе
собственные кадры стенда.

## Устройство

`codec.py` — раскладка кадров, зеркало `message-gateway/src/can-codec.cpp`.
`bus.py` — доступ к шине: socketcan и slcan, приём в своём потоке,
переподключение раз в 5 секунд.
`server.py` — Flask, поток выдачи, лента последних 300 кадров.

## Проверено

Стенд и шлюз сведены через пару виртуальных портов (`socat`), то есть тем же
путём, что и физический адаптер:

- шлюз принимает время и координаты — `source: can`, `valid: true`, координаты
  совпадают с отправленными;
- обнаружения с двух камер приходят кадром `02 01 04 03` и разбираются как
  «2 обн. · человек · критическая опасность · камеры 1, 2»;
- через секунду молчания нагрузка гаснет — шлюз чистит её по `payload_ttl_ms`.
