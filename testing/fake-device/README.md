# fake-device — поддельная плата техзрения

Стенд для мастера и интерфейса: изображает вторую плату с модулем neural там, где
настоящей нет. Отвечает на REST media-center из памяти: паспорт, камеры,
конфигурации, видеопотоки, слоты. Видео, сигналинга и NPU у неё нет.

Нужен, чтобы на одной плате увидеть всё, что зависит от числа устройств: выбор
устройства в техзрении, сводку `GET /api/neural/status`, плитку главной, классы
журнала и КРСПС с нескольких плат.

## Запуск

На машине мастера, из корня репозитория:

```
bash testing/fake-device/run.sh start                # контейнер + регистрация в реестре
bash testing/fake-device/run.sh mode no_module       # 404 на /neural/*, neural в модулях остаётся
bash testing/fake-device/run.sh mode bare            # 404 и пустой список модулей
bash testing/fake-device/run.sh mode ok              # обратно
bash testing/fake-device/run.sh offline              # пауза контейнера: плата не в сети
bash testing/fake-device/run.sh online               # снова в сети, адрес тот же
bash testing/fake-device/run.sh stop                 # убрать из реестра и сверить его с копией
```

`start` сохраняет `devices.json` в `~/devices.json.bak-fake`, поднимает контейнер из
образа мастера `varan/detection-service:latest` (в нём уже есть FastAPI и uvicorn) на
мосту docker и регистрирует плату через `POST /api/devices`. `fastapi` работает в
сети хоста и видит адрес моста, обычно `172.17.0.2`. `stop` удаляет плату из
реестра, контейнер — следом, и сравнивает реестр с копией.

Переменные: `FAKE_ID` (`fake-second`), `FAKE_TITLE` (`Хвостовой вагон`),
`FAKE_CONTAINER` (`fake-device`), `FAKE_IMAGE`, `FAKE_API`
(`http://127.0.0.1:8000/api`), `FAKE_BACKUP`.

Реестр боевой: пока плата зарегистрирована, её видят все, кто открыл интерфейс, а
главная показывает её в «требуют внимания», если она не в сети. После проверки —
`stop`.

## Что отдаёт

| Ручка | Содержимое |
|-------|------------|
| `/system/info` | `device_id`, модуль `neural`, платформа RK3588 на 3 ядра NPU |
| `/camera` | одна камера `camera_f1` с назначением neural |
| `/neural/status` | два слота: `fake_stream` работает, `fake_broken` с кодом 6001 |
| `/neural/configurations` | `railway_camera` (тот же id, что на .102) и `fake-config` со своими классами и суперклассом |
| `/neural/classes`, `/neural/superclasses` | классы конфигураций выше |
| `/neural/state`, `/neural/streams` | слоты и видеопотоки; запись держится в памяти до перезапуска |
| `/neural/start`, `/restart`, `/stop` | принимаются и ничего не делают |

`railway_camera` совпадает по id с конфигурацией .102 — на нём видно правило «совпавший
id берётся с первой платы, начиная с устройства по умолчанию». `fake-config` есть
только здесь — по нему видно, что журнал и КРСПС собирают классы со всех плат.

## Проверено

На .102, 11.10.2026: сводка отдаёт `ok` с двумя слотами, `no_module` на 404,
устройство пропадает из ответа в режиме `bare`, `offline` при остановленном контейнере.
В интерфейсе — выбор устройства, «Инференс» второй платы, редактор с камерой только
этой платы, «Нейросети» второй платы, конфигурация `fake-config` в фильтре журнала,
плитка главной по двум платам.
