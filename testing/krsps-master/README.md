# krsps-master — эмулятор ведущего АС КРСПС

Ведущий Modbus RTU по протоколу АС КРСПС v2.3 на COM-порту ПК со страницей.
Через USB–RS485 (CH340) говорит с модулем `modbus` шлюза на плате так же, как
настоящая АС КРСПС: пишет время и GPS, читает состояние и записи, отмечает
прочитанные. Пара к нему на pty без железа — `testing/krsps-modbus/stand.py`.

## Запуск

```
pip install -r requirements.txt
python server.py --device COM6      # порт открывается сразу
python server.py                    # порт и всё прочее — со страницы
python server.py --selftest         # цикл против ведомого в памяти, без порта
```

Страница: http://localhost:8767 (`--port` — другой). Настройки страницы
сохраняются в `settings.json` рядом с сервером.

## Цикл

Цикл запускается кнопкой в шапке.

1. В начале обмена и после 3 таймаутов подряд — чтение 0x1000–0x1005 (0x04);
   пока блок не прочитан, остального нет.
2. Раз в период (5 с): время и GPS в Holding 0x2000–0x200B (0x10), чтение
   0x1006 и регистров состояния (их число — из 0x1005).
3. Есть записи — выборка до конца в этом же проходе:
   - 0x1002 = L > 0 — заголовок с данными разом, ⌊125/L⌋ записей в запросе,
     не больше окна 0x1003;
   - 0x1002 = 0 — сначала 0x2000–0x2001 (длина, номер), потом данные; запись
     длиннее 125 регистров читается частями;
   - после каждой порции — отметка 0x0001 в 0x1000–0x1002 и снова 0x1006;
     за проход не больше записей, чем было в 0x1006 в его начале;
   - выборка дольше периода — между порциями снова время и GPS.

Ответ ждётся `timeout_ms` (300 мс), между кадрами не меньше 2 мс.

## Настройки

| Группа | Что |
|--------|-----|
| Порт | COM, скорость, чётность, биты, стоп; открыть/закрыть |
| Ведомый и цикл | адрес (20), период, таймаут, «отмечать прочитанные» |
| Время | часы ПК в UTC ± сдвиг или заданное время, дальше идущее ходом; «слать время» |
| GPS | точка, неподвижна или гуляет в пределах ±0.02°; «слать GPS» (иначе нули); буквы полушарий: как живой ведущий (0x2006 = N/S) или по протоколу (0x2006 = E/W) |

Ручное: запрос любой функцией 0x03/0x04/0x06/0x10, блок 0x1000–0x1005,
отметка заданных номеров (после неё — 0x1006 до и после), время и GPS адресом 0.
Порча следующего запроса: битый CRC (ведомый должен молчать) и мусор перед
кадром (ведомый должен ответить).

## Что эмулятор проверяет у ведомого

Нарушения — жёлтые строки ленты и счётчик «Нарушений»:

- адрес или функция ответа не те, длина ответа не по запросу, лишние байты,
  ответ на широковещательный запрос или на кадр с битым CRC;
- длина записи меньше 2 или больше окна; не равна 0x1002, если та не 0;
- номер записи не следующий за последним полученным (пропуск; после 65535 —
  0); повтор уже отмеченной записи;
- после принятой отметки 0x1006 не уменьшилось;
- 0x1006 > 0, а в 0x2000 нули.

Повтор при выключенной отметке нарушением не считается, только счётчиком.

## Страница

Плитки: порт, ведомый (на связи, давность ответа), блок 0x1000–0x1005,
состояние 0x1006+. Счётчики обмена. Таблица полученных записей — новые сверху,
пакет 28163 расшифрован словарями шлюза (код, роли камер по маске, зона),
строка раскрывается в регистры. Лента обмена: время, направление, hex кадра,
смысл, длительность ответа; фильтр «только ошибки», пауза, очистка.
Хранится только в памяти: 500 записей и 2000 строк ленты.
