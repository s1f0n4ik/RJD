## Master и minion

Развёртывание в Docker делится на два вида compose-файлов (лежат в репозитории).

| | Master | Minion |
|---|---|---|
| Файл | `docker-compose.master.yml` | `docker-compose.minion.yml` |
| Отвечает за | Фронт, шлюз CAN/WebSocket/Modbus, маршрутизацию устройств, мастер обнаружений (`detection-service`: журнал, отправка в АС КРСПС) | Связь с локальным media-center (сигналинг), записи на диске |
| Сколько | **Один на всю сеть** | **По одному на каждое устройство с media-center** |

- Устройство с media-center **и** фронтом — разворачивать **оба** вида.
- Устройство только с media-center — только **minion**.
- Сигналинг работает лишь там, где поднят minion, — поэтому minion обязателен на каждой плате с ядром.

## Логика media-center

Поведение ядра задаётся флагами в `media-center.service`:

| Флаг | Значение |
|---|---|
| `--modules` | Доступные модули: `neural`, `birdview` или оба через запятую. Плата только с техзрением — `neural`, только с 360 — `birdview`; всё на одной машине — оба. |
| `--gateway-ip` | IP устройства, где запущен **master** (там живёт шлюз отправки сообщений; от него же время и GPS) |
| `--detection-ip` | IP устройства, где запущен **master** (там живёт мастер обнаружений). Без пары `--detection-ip`/`--detection-port` треки никуда не уходят: журнал пуст, в АС КРСПС ничего не отправляется |
| `--varan-root` | Корень с конфигурациями, калибровками и моделями (`/var/lib/varan` — новые, `/home/orangepi/varan` — старые) |
| `--rest-port` `--signaling-*` `--gateway-port` `--detection-port` | Порты (7777, 8765, 50051, 50052). **Оставлять как есть**, донастройки не требуют |

# Часть 2. Установка по шагам

## Быстрый путь: готовый образ

Образ `orangepi5pro-neural-<дата>-<sha>.img.xz` снят с полностью развёрнутой платы техзрения и содержит всё из шагов 1–8: master + minion, media-center с `--modules=neural`, GStreamer 1.28, рантайм NPU, нейромодели, тайлы карты, wstunnel, часовой пояс `Europe/Moscow`, удалённый brltty.

1. Записать `.img.xz` на SSD balenaEtcher'ом — архив распаковывать не нужно. SSD — от 32 ГБ. `rkspi_loader.img` — на SD-карту, как обычно.
2. Включить плату. При первом запуске она сама:
   - растягивает корневой раздел на весь SSD (разовая служба `varan-expand-rootfs`) — шаг с `parted` из подготовки **не нужен**;
   - создаёт новые SSH-ключи (штатный `orangepi-firstrun`);
   - получает IP по DHCP — смотреть в роутере. Постоянный адрес задаётся в NetworkManager (`nmtui` или `nmcli`).
3. Открыть `http://<IP>/app` и пройти [порядок первичной настройки](#порядок-первичной-настройки). Реестр устройств в образе пустой — плату добавить сканом на `/app/devices`.

Для платы с 360 образ подходит после правки юнита: `--modules=birdview` (или `birdview,neural`) в `/etc/systemd/system/media-center.service` и перенос `surround_view` по [шагу 8](#шаг-8-перенос-настроек).

## Подготовка: образ и файловая система

1. Записать `orangepi5pro_rsm.img` на SSD, `rkspi_loader.img` — на SD-карту (загрузчик SSD).
2. Подключиться по SSH (IP выдаётся по DHCP — смотреть в роутере; логин/пароль `orangepi` / `orangepi`).
3. Расширить файловую систему SSD до максимума:

```bash
sudo parted /dev/nvme0n1
# в интерактивной строке:
resizepart 2 100%     # согласиться на все запросы
quit

sudo partprobe /dev/nvme0n1   # если команда не найдена — пропустить
sudo resize2fs /dev/nvme0n1p2
```

4. Часовой пояс — в стоковом образе Orange Pi стоит `Asia/Shanghai`:

```bash
sudo timedatectl set-timezone Europe/Moscow
```

> Если образ `orangepi5pro_rsm.img` уже установлен, переходите сразу к [Шагу 6](#шаг-6-сборка-media-center).

### 5.3. Рантайм нейросети

Скопировать `Доп пакеты/Либа для нейронки/librknnrt.so` (2.3.2) в `/usr/lib/librknnrt.so`. В стоковом образе там лежит старая 1.4.0 — её убрать **из `/usr/lib`**: у копии тот же soname, ldconfig на неё ругается.

## Шаг 6. Сборка media-center

На старых устройствах использовать путь `/home/orangepi/varan/media-center`.

## Шаг 7. Сервис media-center

Создать `/etc/systemd/system/media-center.service` (содержимое — из файла `media-center.service`). Ключевая часть:

```ini
StateDirectory=varan
WorkingDirectory=/opt/media-center/1.1.0
ExecStart=/bin/bash -lc 'source /opt/gstreamer-1.28/env.sh && exec /opt/media-center/1.1.0/media-center \
    --rest-port=7777 --signaling-ip=127.0.0.1 --signaling-port=8765 \
    --modules=birdview,neural \
    --varan-root=/var/lib/varan \
    --gateway-ip=127.0.0.1 --gateway-port=50051 \
    --detection-ip=127.0.0.1 --detection-port=50052'
```

Смысл флагов — в разделе [Логика media-center](#логика-media-center). `--modules` выставить под плату (только техзрение — `neural`); `--gateway-ip` и `--detection-ip` — адрес master, если он на другой машине. Порты оставлять как есть; сигналинг работает только при поднятом minion.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now media-center.service
systemctl is-active media-center                 # active
head -1 $(ls -t /var/lib/varan/logs/*.log | head -1)   # первая строка лога — argv запуска
```

### 7.1. Внешние диски записи

Внешние USB-диски монтируются сами в `/storage/media/<метка ФС или UUID>`, storage-service включает их в пул записи. Подходят ext4 и exFAT; остальные ФС монтируются только для чтения и показываются как «не подходит». Рабочий стол такие диски не видит и не монтирует.

```bash
sudo apt-get install -y exfatprogs exfat-fuse    # fsck.exfat и exFAT через FUSE: ядро платы без exfat
sudo install -m 0755 varan-media /usr/local/sbin/varan-media
sudo install -m 0644 varan-media@.service /etc/systemd/system/
sudo install -m 0644 90-varan-media.rules /etc/udev/rules.d/
sudo mkdir -p /storage/media
sudo systemctl daemon-reload && sudo udevadm control --reload
```

Диск подключать со своим питанием или через USB-хаб с питанием. USB-порт платы отдаёт диску до 900 мА, а без USB-PD плата сидит на 5 В: вместе с нагрузкой NPU и декодеров этого может не хватить, и плата перезагрузится.

Диски форматировать на самой плате. `mkfs.ext4` из свежих систем (e2fsprogs 1.47+) включает `orphan_file`, и `e2fsck` платы такой диск не проверит («Get a newer version of e2fsck»). На другом компьютере — только с отключённым свойством:

```bash
sudo mkfs.ext4 -L ARCHIVE1 /dev/sdX1                     # на плате
sudo mkfs.ext4 -O ^orphan_file -L ARCHIVE1 /dev/sdX1     # на системе с e2fsprogs 1.47+
```

Проверка после подключения диска:

```bash
journalctl -t varan-media -n 5       # «/dev/sdX1 (ext4) mounted at /storage/media/…»
findmnt -R /storage/media
cat /storage/archive/target.json     # цель записи переключилась на диск
```

## Шаг 8. Перенос настроек

Все файлы — в папке `Доп пакеты`. Переносятся с сохранением путей (корень varan — зеркало).

- **Тайлы карты журнала** — папки из `journal/` в `/storage/journal` (как есть).
- **Калибровки и модели** — в корень varan (`/var/lib/varan` или `/home/orangepi/varan`) перенести `surround_view`. По необходимости:
  - пресеты калибровки — `calibration/calibration_settings.json` + папка `calibration/maps/`;
  - модели сшивки — `presets/models/`;
  - нейросеть — `neural` с конфигурацией модели и самой моделью.

В `neural/configurations.json` путь к модели абсолютный (`/home/orangepi/varan/...`). На новых машинах переписать его на корень `/var/lib/varan`, отдать корень `orangepi` (media-center работает от него) и перезапустить ядро:

```bash
sed -i 's#/home/orangepi/varan/#/var/lib/varan/#g' /var/lib/varan/neural/configurations.json
grep -o '"model_path":"[^"]*"' /var/lib/varan/neural/configurations.json
sudo chown -R orangepi:orangepi /var/lib/varan
sudo systemctl restart media-center
```

> Отдельные параметры можно переносить со старого устройства для использования в новой версии.

# Часть 3. Модули фронта

Фронт (`shit/frontend`) — единое React-приложение на `/app`, которое раздаёт **master**: одна левая рельса разделов, модули — её разделы со своими подразделами (`src/screens`), их логика — в `src/features`. Прямой эфир `/translation` — отдельный экран без рельсы и без авторизации (на изделии его открывает автозапуск браузера). MUI и старая оболочка удалены полностью (сентябрь 2026).

## Разделы интерфейса

| Раздел | Код | Маршрут | Наблюдатель | За что отвечает |
|---|---|---|---|---|
| Главная | `screens/home` | `/app` | видит | Плитки разделов с живыми сводками, устройства, накопители, последние обнаружения |
| Камеры | `screens/cameras` | `/app/cameras` | только просмотр | Добавление, скан сети, правка камер и потоков, назначения потоков на устройства |
| Отображение | `screens/live` | `/app/live` | скрыт | Редактор сеток камер, сохранение раскладок, запуск эфира |
| Архив | `screens/archive` | `/app/archive` | полностью | Записи по устройствам: календарь, таймлайн, плеер, склейка и выгрузка |
| Устройства | `screens/devices` | `/app/devices` | скрыт | Реестр одноплатников, скан сети, маршрутизация модулей и назначений |
| Конфигурации | `screens/configurations` | `/app/configurations` | скрыт | Конфигурация изделия (РСМ-2000, Искра): выбор одним действием переключает и шлюз АС КРСПС, и фильтр мастера обнаружений |
| Техническое зрение | `screens/neural` + `features/neural` | `/app/neural/{configs,streams,inference,journal}` | только журнал | Нейросети, видеопотоки (вход модели), инференс по устройствам (слоты, NPU), журнал обнаружений с картой, сводкой и выгрузкой — журнал ведёт мастер обнаружений |
| Система 360 | `screens/surround` + `features/birdview` | `/app/surround/{calibration,projection,linker,configurator,mapping}` | скрыт | Калибровка, сборка, отображение, конфигуратор, сопоставление камер и калибровок |
| АС КРСПС | `screens/krsps` + `features/krsps` | `/app/krsps/{websocket,can,modbus,taxonomy,time}` | скрыт | Шлюз сообщений: модули активной конфигурации (WebSocket ЦПУ, шина CAN, Modbus RTU), таблица соответствий классов, время и GPS |
| Прямая трансляция | `screens/translation` | `/translation[/<раскладка>]` | открыт | Полноэкранный вывод сохранённой сетки, WebRTC-плееры, без авторизации |

Прежние адреса живут редиректами: `/new/*` → `/app/*`, `/kiosk` → `/translation`, `/app/birdview/*` → `/app/surround/*`. Права задаются признаком `admin` в `src/app/nav.ts`: закрытый раздел наблюдателю не показывается ни в рельсе, ни на главной, прямой адрес уводит на главную. Диалога повышения прав нет — нужны права, войдите администратором.

## Порядок первичной настройки

После установки админ проходит по разделам сверху вниз — так система из чистого состояния доводится до рабочего. Всё, кроме просмотра, доступно только под админом.

1. **Устройства** (`/app/devices`) — добавить платы сканом сети, затем в таблице маршрутизации назначить, какой модуль (техническое зрение / 360) и какие типы камер обслуживает каждое устройство. *Зачем: без маршрутизации фронт не знает, на какое устройство слать камеры и запросы модулей.*
2. **Камеры** (`/app/cameras`) — добавить камеры нужных типов; тип определяет устройство-владельца по маршрутизации. *Зачем: источники кадров для эфира, архива и аналитики.*
3. **Техническое зрение** (`/app/neural`) — выбрать устройство; в «Нейросетях» выбрать или загрузить модель, настроить классы и трекер; в «Видеопотоках» собрать вход модели из камер; в «Инференсе» задать слоты и запустить; при необходимости задать лимиты хранилища журнала. *Зачем: включить детекцию объектов и журнал обнаружений.*
4. **Система 360** (`/app/surround`) — пройти этапы калибровка → сборка → отображение → сопоставление камер с калибровками. *Зачем: собрать панораму/объёмный вид и коррекцию изображения.*
5. **Конфигурации** (`/app/configurations`) — выбрать конфигурацию изделия (РСМ-2000, Искра). *Зачем: она задаёт и модули шлюза, и правила, по которым мастер обнаружений склеивает треки и решает, что отправлять.*
6. **Шлюз (БИУС)** (`/app/krsps`) — настроить модули активной конфигурации: CAN (адреса, PGN), адрес WebSocket БИУС, Modbus RTU (порт) для Искры; заполнить таблицу соответствий классов, задать часовой пояс единого времени. *Зачем: отправка обнаружений в БИУС и единое время для журнала и архива.*
7. **Отображение и трансляция** (`/app/live`, `/translation`) — собрать раскладки камер и сохранить; трансляция выводит их на месте. *Зачем: рабочие экраны оператора.*

> Порядок важен: маршрутизация устройств (шаг 1) — предпосылка для всего остального, а камеры (шаг 2) нужны разделам аналитики.
