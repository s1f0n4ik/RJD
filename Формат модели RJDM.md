# Формат модели `.rjdm` — инструкция для экспорта

Документ для разработчиков приложения, которое готовит модели для RJD. Описывает, как упаковать
`.rknn` веса вместе с классами, суперклассами и описанием в один файл `.rjdm`.

В RJD модель только **импортируется**: из манифеста берутся значения конфигурации нейросети
(классы, суперклассы, цвета, размер входа), чтобы их не подбирать вручную. Экспорт делает ваше приложение.

Версия формата: **1**.

## 1. Что такое `.rjdm`

ZIP-архив без сжатия и без шифрования с двумя файлами:

| Файл в архиве   | Обязателен | Содержимое                              |
|-----------------|------------|-----------------------------------------|
| `manifest.json` | да         | Описание модели, UTF-8 JSON             |
| `weights.rknn`  | да         | Готовый `.rknn`, байт в байт как из toolkit |

Требования к архиву:

- Метод сжатия **только `STORED` (0)** у обоих файлов. RJD грузит веса напрямую из архива, без распаковки.
- `manifest.json` лежит **первым** в архиве.
- Имена файлов в архиве только латиницей и ровно такие, как в таблице. Других файлов не кладите
  (лишние RJD проигнорирует, но не прочитает).
- Без шифрования, без многотомности, без ZIP64, если файл меньше 4 ГБ.
- Расширение файла `.rjdm`. Имя файла любое, лучше `<id модели>.rjdm`.

## 2. Кодировка и русский язык

- `manifest.json` — **UTF-8 без BOM**. Кириллицу пишите как есть, не через `\uXXXX`
  (экранирование допустимо, но `ensure_ascii=False` обязателен: так манифест можно читать глазами).
- Текст приводите к нормальной форме **NFC** (без «й» из «и» + комбинируемый символ). Пример: `unicodedata.normalize("NFC", s)`.
- Не обрезайте и не транслитерируйте русские названия. Не заменяйте «ё» на «е».
- Служебные идентификаторы (`id` модели, `key` суперкласса, `server_id`) — только `[a-z0-9_-]`, латиница.
  Русский текст идёт **только** в полях `name`, `description`, `notes`.
- Строки без управляющих символов, кроме `\n` в `description` и `notes`.

## 3. `manifest.json`

### 3.1 Пример

```json
{
  "format": "rjdm",
  "schema_version": 1,

  "id": "rail-objects",
  "name": "Объекты пути",
  "version": "2026.11.1",
  "description": "Детектор предметов и людей на путях.\nОбучен на съёмке станции.",
  "author": "Отдел аналитики",
  "created_at": "2026-11-18T10:00:00Z",

  "weights": {
    "file": "weights.rknn",
    "size": 11534336,
    "sha256": "9f2c…64 символа hex…",
    "target_platform": "rk3588",
    "toolkit_version": "2.3.2",
    "quantized": true
  },

  "model": {
    "task": "detect",
    "family": "yolo11",
    "input_width": 640,
    "input_height": 640,
    "input_channels": 3,
    "output_layout": "split_levels",
    "class_count": 3
  },

  "superclasses": [
    { "key": "person",   "name": "Человек",     "color": "#F5A623" },
    { "key": "obstacle", "name": "Препятствие", "color": "#9F93F5" }
  ],

  "classes": [
    { "id": 0, "name": "Человек в жилете", "superclass": "person",   "color": "#F5A623", "server_id": "person_vest" },
    { "id": 1, "name": "Чемодан",           "superclass": "obstacle", "color": "#9F93F5", "server_id": "suitcase" },
    { "id": 2, "name": "Коляска",           "superclass": "obstacle", "color": "#7E6BE0" }
  ],

  "notes": "Порог confidence ниже 0.4 даёт много ложных на рельсах."
}
```

### 3.2 Верхний уровень

| Поле             | Тип    | Обяз. | Описание |
|------------------|--------|-------|----------|
| `format`         | строка | да    | Всегда `"rjdm"` |
| `schema_version` | число  | да    | Сейчас `1`. Менять только при несовместимых изменениях |
| `id`             | строка | да    | Идентификатор модели, `[a-z0-9_-]`, до 64 символов |
| `name`           | строка | да    | Отображаемое название модели, любой язык, до 120 символов |
| `version`        | строка | нет   | Версия модели, свободный текст, до 32 символов |
| `description`    | строка | нет   | Описание, до 2000 символов |
| `author`         | строка | нет   | Кто собрал, до 120 символов |
| `created_at`     | строка | нет   | Время сборки, ISO 8601, UTC (`2026-11-18T10:00:00Z`) |
| `weights`        | объект | да    | См. 3.3 |
| `model`          | объект | да    | См. 3.4 |
| `superclasses`   | массив | да    | См. 3.5. Может быть пустым `[]` |
| `classes`        | массив | да    | См. 3.6 |
| `notes`          | строка | нет   | Заметки для оператора, до 4000 символов |

Неизвестные поля RJD игнорирует, так что добавлять свои можно. Но не используйте для них имена из таблиц выше.

### 3.3 `weights`

| Поле              | Тип    | Обяз. | Описание |
|-------------------|--------|-------|----------|
| `file`            | строка | да    | Всегда `"weights.rknn"` |
| `size`            | число  | да    | Размер `weights.rknn` в байтах |
| `sha256`          | строка | да    | SHA-256 файла `weights.rknn`, 64 символа hex в нижнем регистре |
| `target_platform` | строка | да    | Например `rk3588`. Платформа, под которую собран `.rknn` |
| `toolkit_version` | строка | нет   | Версия RKNN-Toolkit2 (`2.3.2`) |
| `quantized`       | булево | да    | Модель квантована в int8 или нет |

### 3.4 `model`

Описание того, что RJD иначе узнавал бы только через `rknn_init`.

| Поле             | Тип    | Обяз. | Описание |
|------------------|--------|-------|----------|
| `task`           | строка | да    | `detect` или `segment` |
| `family`         | строка | нет   | `yolo11`, `yolo26` и т. п. Только для показа |
| `input_width`    | число  | да    | Ширина входа в пикселях (>0) |
| `input_height`   | число  | да    | Высота входа в пикселях (>0) |
| `input_channels` | число  | нет   | По умолчанию `3` |
| `output_layout`  | строка | да    | Раскладка выходов, см. ниже |
| `class_count`    | число  | да    | Число классов в выходных тензорах. Должно равняться `len(classes)` |

Значения `output_layout`:

| Значение            | Выходы модели |
|---------------------|---------------|
| `single`            | Один выход `[1, 4+nc, anchors]`, боксы декодированы, скоры после sigmoid |
| `split_levels`      | Девять выходов, по три на уровень: бокс, скоры, сумма скоров |
| `single_seg`        | Как `single`, плюс коэффициенты масок `[1, 4+nc+nm, anchors]` и прото |
| `split_levels_seg`  | Как `split_levels`, плюс тензор масок на уровень и прото |

При `task: "segment"` layout обязан быть `single_seg` или `split_levels_seg`, при `detect` — `single` или `split_levels`.
Если не уверены в layout, **не угадывайте**: возьмите его из реальных форм выходных тензоров собранной модели.

### 3.5 `superclasses[]`

Суперкласс — группа классов (человек, препятствие, техника).

| Поле    | Тип    | Обяз. | Описание |
|---------|--------|-------|----------|
| `key`   | строка | да    | Идентификатор, `[a-z0-9_]`, уникален в массиве |
| `name`  | строка | да    | Отображаемое название (русское), до 120 символов |
| `color` | строка | нет   | `#RRGGBB` |

### 3.6 `classes[]`

| Поле         | Тип    | Обяз. | Описание |
|--------------|--------|-------|----------|
| `id`         | число  | да    | Номер класса = индекс в выходе модели (0, 1, 2…). Целое, ≥ 0 |
| `name`       | строка | да    | **Отображаемое название** (русское), до 120 символов. Это то, что видит оператор |
| `superclass` | строка | нет   | `key` из `superclasses`. Если задан, такой `key` должен существовать |
| `color`      | строка | нет   | `#RRGGBB`. Если нет, RJD возьмёт цвет суперкласса |
| `server_id`  | строка | нет   | Идентификатор, который уходит на сервер, `[a-z0-9_-]`. Если нет, остаётся пустым |

`id` и `name` — разные вещи: `id` — число для модели, `name` — текст для человека. Не подставляйте одно вместо другого
и не делайте `name` из `id`.

## 4. Правила проверки (экспортёр должен выполнить до записи)

1. `classes` содержит ровно `class_count` записей, `id` идут **0…class_count−1** без пропусков и повторов.
2. `name` у каждого класса и суперкласса непустой после обрезки пробелов; `name` классов уникальны.
3. `key` суперклассов уникальны. Каждый `classes[].superclass` ссылается на существующий `key`.
4. `weights.size` и `weights.sha256` посчитаны по файлу, который лежит в архиве, а не по исходнику до копирования.
5. `class_count` сверен с реальной моделью: число классов, зашитое в выходные тензоры, равно `class_count`.
   Для `single` это `dims[1] − 4`, для сегментации ещё минус число коэффициентов масок.
6. Цвета строго `#RRGGBB` (6 hex-цифр).
7. Текстовые поля в NFC, без управляющих символов, в пределах указанных длин.
8. Манифест сериализован как UTF-8 без BOM, и обратное чтение даёт ту же кириллицу.

## 5. Эталонная упаковка (Python)

```python
import hashlib, json, unicodedata, zipfile

def nfc(v):
    if isinstance(v, str):
        return unicodedata.normalize("NFC", v)
    if isinstance(v, list):
        return [nfc(x) for x in v]
    if isinstance(v, dict):
        return {k: nfc(x) for k, x in v.items()}
    return v

def pack(rknn_path: str, manifest: dict, out_path: str) -> None:
    with open(rknn_path, "rb") as f:
        weights = f.read()
    manifest = nfc(manifest)
    manifest["format"] = "rjdm"
    manifest["schema_version"] = 1
    manifest["weights"].update(
        file="weights.rknn",
        size=len(weights),
        sha256=hashlib.sha256(weights).hexdigest(),
    )
    if len(manifest["classes"]) != manifest["model"]["class_count"]:
        raise ValueError("class_count не равен числу классов")
    text = json.dumps(manifest, ensure_ascii=False, indent=2)
    with zipfile.ZipFile(out_path, "w", zipfile.ZIP_STORED) as z:
        z.writestr("manifest.json", text.encode("utf-8"))
        z.writestr("weights.rknn", weights)
```

## 6. Как проверить свой экспорт

1. `python -m zipfile -l model.rjdm` показывает ровно `manifest.json` и `weights.rknn`.
2. `unzip -v model.rjdm` показывает метод `Stored` у обоих файлов.
3. `unzip -p model.rjdm manifest.json` выводит читаемую кириллицу (не `\u04..`) и нет BOM в первых байтах.
4. `unzip -p model.rjdm weights.rknn | sha256sum` равен `weights.sha256` из манифеста.
5. Файл `weights.rknn` из архива совпадает с исходным `.rknn` байт в байт.
6. Тест на русские классы: название с «ё», «й», пробелом и кавычками («Человек в «жилете»») проходит туда и обратно без искажений.

## 7. Что RJD делает при импорте

Для справки, чтобы понимать, зачем нужны поля:

- При загрузке `.rjdm` бэкенд читает только `manifest.json`, веса на NPU не грузит и `rknn_init` на этом шаге не вызывает.
- Проверяет `format`, `schema_version`, правила из раздела 4, метод `STORED`, размер и sha256 весов. Файл, не прошедший проверку, не принимается, оператор видит причину.
- В списке моделей у `.rjdm` есть описание из манифеста. Редактор конфигурации нейросети заполняет из него классы (id → `name`, `superclass`, `color`, `server_id`), суперклассы и название конфигурации.
  Новую конфигурацию без классов заполняет сразу, у конфигурации с классами показывает кнопку «Заполнить из модели».
  Значения из манифеста — это значения по умолчанию, оператор может их потом изменить.
- Размер входа из манифеста бэкенд использует, чтобы согласовать размер холста потока с моделью до сохранения конфигурации.
- Устройство получает `.rjdm` как обычный файл модели и берёт из него только `weights.rknn`.
  Прочитав модель через `rknn_init`, оно записывает в конфигурацию реальные размер входа, layout и число классов; редактор подсвечивает, если число описанных классов не равно числу классов в модели.
- Пороги (`nms`, `confidence`), трекер и зоны **в манифесте не задаются**: они остаются в конфигурации RJD.
- Файлы с `schema_version` больше поддерживаемой отклоняются. Голые `.rknn` без манифеста продолжают работать как раньше.

## 8. Совместимость и будущие версии

- В версии 1 можно только добавлять необязательные поля. Любое удаление, переименование или смена смысла поля — это `schema_version` 2.
- Если ваше приложение добавляет свои поля, дайте им префикс `x_` (например `x_dataset`), чтобы они не пересеклись с будущими полями формата.
